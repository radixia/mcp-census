# 0002 — D3 detects a modern MCP endpoint by its `405`, not by a successful `HEAD`

- **Date:** 2026-08-04
- **Status:** accepted

## Context

The brief specified D3 as `HEAD /mcp`, plus `mcp.<apex>` and `api.<apex>/mcp`.

The `2026-07-28` Streamable HTTP transport makes this unworkable. The MCP endpoint
is **POST-only**, and a server that supports only this revision **SHOULD** answer
`GET` or `DELETE` with `405 Method Not Allowed`. A successful `HEAD` therefore
indicates almost anything *except* a modern MCP endpoint.

Detecting one positively requires a `POST`. But the crawler ethics rules permit
`POST` only *after* discovery has already produced an endpoint — and D3 *is*
discovery. Taking the obvious route would mean POSTing to undiscovered paths on
domains that never asked us to, widening the crawl envelope for the sake of
recall.

Three options were considered:

1. Treat `405` as the positive signal.
2. Permit one unauthenticated `server/discover` POST to up to three conventional
   paths per apex.
3. Drop conventional-path probing and rely on D1/D2/D4 only.

## Decision

**Option 1.** D3 issues `GET`/`HEAD` to the conventional locations and treats
`405 Method Not Allowed` as positive evidence of a modern MCP endpoint. `404`
remains negative. A `400` carrying a recognisable modern JSON-RPC error body
(`UnsupportedProtocolVersionError`, `HeaderMismatch`) is also positive.

## Consequences

- The crawl envelope does not widen. `GET`/`HEAD` on a conventional path stays
  inside what the ethics document already promises, and no ethics amendment is
  needed.
- It is exactly what the specification prescribes servers to do, so it is
  defensible in public rather than clever-but-questionable.
- It is a genuinely novel detection technique as far as we can tell, and worth
  writing up in the methodology.
- **Known weakness, to be declared in Limitations:** `405` is not unique to MCP.
  Any POST-only endpoint at `/mcp` answers the same way, and a reverse proxy may
  return `405` for its own reasons. D3 alone is therefore weak evidence; it is
  useful for locating an endpoint to hand to D5, and it must not be scored as a
  confirmed MCP server on its own.
- Because a `405` yields an endpoint, D5 may then POST to it legitimately, which
  is what confirms the finding.
